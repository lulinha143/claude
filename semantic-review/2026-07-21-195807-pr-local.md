# Decoration placement, per-item pixel art, and per-department room identity

This pass reworks the decoration system across three fronts: placement is now driven by an explicit per-item spec (`placementSpecs.ts`) instead of filename regex and a coarse "large items" set; every one of the 32 catalogue props is redrawn as a distinct pixel-art sprite (`decoArt.tsx`) chosen by exact id while the coarse `kind` still drives sound/toggle/class behaviour; the live drag is coalesced to one recompute per frame with a continuous inset clamp and region hysteresis so previews glide instead of snapping; and each department gets its own CSS-driven wall/floor/window/lighting identity plus built-in table/shelf surfaces aligned to the real placement regions. Typecheck, lint, and the two new test files all pass, and reduced-motion is comprehensively handled.

**Watch for:** `placementSpecs.ts` documents itself as the single source of truth consulted by "preview, hit-testing, rendering, collision and persistence," but only `footprint` is actually wired in — `scale`, `baseline`, `minClearance`, `mirrorable`, and `allowSceneryOverlap` are inert (Medium, confirmed). The intended per-item visual scaling (window-view 1.1×, billboard 1.15×, label-maker 0.8×…) therefore never renders. The new per-surface drag-ghost anchors for wall/ceiling are hand-tuned and only directionally verified; the wall value looks ~5% off the geometry-derived ideal, so a small post-drop shift is possible (Medium, possible). Minor: aquarium/beaker bubble stagger silently stopped matching after the SVG structure changed to `<rect>` (Low, confirmed).

## High-level view

Placement metadata moved from implicit classification (regex on the id, a hard-coded `LARGE_DECOS` set, surface-derived sizes) to an explicit hand-authored spec per decoration. A static audit test enforces that all 32 catalogue items declare a spec, so the fallback path is defensive-only. The important caveat is scope: the spec object carries seven fields, but the pipeline only reads `footprint`. The rest describe intent that isn't realized, which is the largest thing to resolve given the goal of visual/logical parity.

The drag pipeline is now frame-coalesced and uses a continuous footprint-aware inset clamp as the fast path, with the old grid search demoted to an exclusion-only fallback. A `preferKind` hysteresis parameter threads from the last preview through `decorationTarget` into `pointerRegionPlacement` so the preview stops flickering between overlapping compatible planes (floor vs tabletop). The drop handler recomputes from the exact release point rather than a stale frame, and the rAF is cancelled on cleanup.

Rendering split cleanly: `decoArt.tsx` owns pixels (per-id sprite on a shared 24×28 grid), while `DecorationProp` keeps owning behaviour via the coarse `kind`. Every catalogue id has an explicit sprite, so the generic crate fallback is unreachable in practice. On/off and poster-variant layering line up with the toggleable kinds; no sprite is left permanently lit by a kind mismatch.

The drag ghost is now anchored per projected surface so a wall item no longer previews at the floor baseline — a real fix. Floor and rug anchors are unchanged; wall and ceiling are newly differentiated and hand-tuned.

Room identity is entirely CSS-driven off an `rd--{roomId}` root class, with the window converted from inline SVG to a styled span plus a scenery/glow child and a mood-light overlay. All 13 room ids have matching CSS blocks; uncovered rooms would degrade to the founder default. Built-in table/shelf spans read their geometry straight from the real placement-region planes, keeping the furniture visual in lock-step with where drops actually land.

Reduced motion is handled globally (a `[data-reduced-motion] * { animation:none }` kill-switch plus the `prefers-reduced-motion` media query), and the new infinite animations (bug idle bob, coffee-drop jiggle) plus the reused `decor__leaf`/`decor__spin`/`decor__bubble` hooks all sit under that umbrella; `DecoArt` additionally omits bubbles entirely under reduced motion.

### Spec as source of truth — only footprint is wired in

`placementSpec(id)` returns seven fields and the module docstring says preview, hit-testing, rendering, collision, and persistence all consult it "so a piece behaves and looks identical everywhere." In practice the only consumer is `footprint()` in `placement.ts`, which reads `footprint.width/height`. A repo-wide search for the other fields finds no production reads:

- `scale` (0.8–1.15 across items) is never applied. `DecoArt` renders every sprite in a fixed 52×60 element and takes no scale prop, so window-view (1.1), billboard/wooden-arch (1.15), and the deliberately-shrunk desk-lamp (0.92), label-maker (0.8), security-cam (0.8) all draw at the same box size. This is the clearest visual-vs-authored divergence in the change.
- `baseline` per-item overrides (rugs 0.82, hammock 0.9, star-ceiling 0.12) are unused; contact anchoring comes from the fixed `.floor__deco--{surface}` CSS transforms and the fixed y=27/28 grid baseline. Rendering stays internally consistent, but the per-item baseline tuning does nothing.
- `minClearance` (0.03 for large items) is never fed into `insetClampToPlane`, which insets only by half the footprint. Large props can therefore sit flush against a plane edge without the intended breathing room.
- `mirrorable` and `allowSceneryOverlap` are inert too — rugs already bypass collision via `isRug()`, so the overlap flag is redundant.

Confidence: confirmed (grep across `src/` shows `placementSpec` consumed only by `footprint`; `DecoArt`'s signature has no scale/baseline/mirror). The fields are exercised only by `placementSpecs.test.ts`, which validates ranges, not effects. Recommend either wiring them up or reducing the spec to what the pipeline uses and rewording the docstring, because the current contract reads as authoritative and will mislead anyone tuning `scale`.

### Continuous inset clamp and the exclusion fallback

`insetClampToPlane` glides a footprint along the (possibly tapered) plane in O(1), and `clampDecorationToRegion` only falls back to the grid search when the inset point still overlaps an exclusion. The plane orientation assumption (`topLeft.y > bottomLeft.y`, non-negative height) is guaranteed by `isNormalizedPlane`, so wall/ceiling planes don't invert. The `dragPlacement.test.ts` sweep confirms sub-0.02 output steps for 0.01 pointer steps, i.e. no discrete snapping — a good, targeted test.

The fallback grid dropped from 28 to 20 steps. Since the fallback now fires only near window/fixture exclusions, the impact is small, but a placement nudged clear of the founder-desk window will land on a slightly coarser lattice than before.

Confidence: confirmed for the clamp math and test coverage; the grid-resolution note is likely-minor.

### Drag ghost anchoring per surface

`ghostAnchorClass` projects the target region's surface (`REGION_KIND_SURFACE` → `projectSurfaceType`) into the floor/rug/wall/ceiling anchor family, so table/shelf/special all collapse to the floor anchor (which matches their placed `.floor__deco--floor` transform and the same support point — consistent). Wall and ceiling now get their own anchors instead of the old shared `--base-anchor`, which is the actual fix: previously a wall poster previewed at the floor baseline (-86.43%) while landing at +50%, a full-height jump.

The residual concern is exactness. Ghost is top-anchored, placed is bottom-anchored, so the ideal relationship is `ghost% ≈ placed% - 100%`:

```
                placed transform   ideal ghost   actual ghost
  floor           +3.57%            -96.43%       -86.43%   (unchanged)
  rug            +17.86%            -82.14%       -73.61%   (unchanged)
  wall           +50%              -50%          -45%       (new)
  ceiling       +100%               0%             0%        (new)
```

Ceiling is exact. Wall is ~5% (≈3px at base scale) shy of the derived ideal — smaller than the pre-existing floor/rug fudge and directionally a large improvement, but since "no post-drop jump" is the explicit invariant, a wall-item drop is worth an eyeball. No automated test asserts ghost-vs-placed alignment.

Confidence: possible (values are self-consistent and clearly better than before; exactness is unverified by tests).

### Sprite/behaviour split and on/off correctness

Every catalogue id maps to an explicit `spriteFor` case (32 of 32), so the generic crate default is unreachable except for unknown ids. Sprites that react to `on` (desk-lamp, mood-lighting, neon-sign, chandelier, star-ceiling, hologram, aquarium, label-maker, security-cam, projector) all correspond to a toggleable `kind` (lamp/screen/aquarium), so nothing is left stuck lit or unable to toggle. The `decor__leaf`/`decor__spin` groups correctly set `transformBox: 'fill-box'` so the reused sway/twinkle keyframes pivot against the sprite box rather than the SVG origin.

Two loose ends. Bubbles are now `<rect>` siblings after the base rects, so `.decor__bubble:nth-of-type(2)` (written for the old `<circle>` structure) matches nothing and the two aquarium/beaker bubbles animate in sync instead of staggered — cosmetic. And four ids resolve to `kind: 'poster'` (blueprint-wall, billboard, window-view, wooden-arch via the `/(poster|blueprint|billboard|window|arch)/` regex) so tapping them advances `data-variant`, but only `motivational-poster` reads `variant`; the others give a press wiggle with no visible slogan change.

Confidence: confirmed.

### Room identity and built-in surfaces

`BuiltInTable`/`BuiltInShelf` derive left/width/bottom/depth straight from `regionsForKinds(roomId, ['tabletop'|'shelf'])[0].plane`, so the drawn furniture coincides with the region a drop commits to — the intended visual/logical lock-step, and a genuinely nice pattern. Rooms without those regions render no built-in surface (guarded by `?`). All 13 room ids (`founder-desk`, `sorting`, `morale`, `procurement`, `construction`, `lab`, `marketing`, `vault`, `research`, `meeting`, `nap`, `basement`, `rooftop`) have matching `.rd--{id}` blocks; the window is hidden for windowless interiors (vault/research/rooftop) and otherwise falls back to the founder default. The old inline-SVG window's `winsky` gradient had no external references, so its removal is clean.

Confidence: confirmed (room-id/CSS-class cross-check).

### Reduced-motion and animation safety

The new infinite animations — `bug-bob` on `.bug` and `mg-drop-jiggle` on falling coffee drops — are both covered by the global `[data-reduced-motion='true'] * { animation: none !important }` rule and the `prefers-reduced-motion` media query, and `.bug` additionally has an explicit reduced-motion override. The bug idle bob is correctly replaced by `bug-squash` on hit (shorthand override), and the coffee jiggle keeps `translate(-50%,-50%)` so the model-based catch geometry is untouched. `DecoArt` omits bubble rects entirely under reduced motion rather than relying only on CSS. The frame-coalesced drag cancels its rAF on cleanup and recomputes the drop from the real release point, so there's no leak and no stale-frame drop.

Confidence: confirmed.
